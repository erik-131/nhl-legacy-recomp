# L2 research: period-end game flow (next period / OT / shootout / game over)

Research note for the next L2 module after docs/l2-rules.md. Labels: **[read]** = from the lifted code of this tree, **[guess]** = inferred. Guest addresses and our own descriptive labels only (no original names, no name maps). Read-only analysis, nothing was run.

## Layout used here
- Game-data block `B = 0x83C87508` (docs/l2-rules.md): clock_sec s16 B+426, clock_sub s16 B+428, period_kind s32 B+432, period_index s32 B+436. New fields found: s16 B+184 shootout attempt counter (zeroed by the shootout reset; value passed on in the shootout setup), s16 B+186/188/190 (also zeroed there, per-side shootout tallies [guess]), u8 B+201 (a "special mode" flag read by two mode predicates), u8 B+203 (set to 1 when a shootout starts), u8 B+207/208 (cleared at each period start), u8 B+424 (which end each team defends, written by 0x833FB6E8).
- **period_kind sentinels [read]:** 3 = any overtime, **255 = shootout in progress** (set with period_index 255 by 0x833FB570), **238 = "no period"** (set by 0x833FB580 with index 238; tested by 0x833FBB58; 0x833FB840 tests 255).
- Flow struct `F = 0x83C1D220` [read]: +0 s32 current flow state (0..13, index into a table of 16-byte rows at 0x83AA5B20: word0 enter, word1 update/after-enter, word2 exit), +12 s32 last stoppage reason, +36 u32 flag word, +52 s32 **period-end outcome code** (see below), +60 s32 intermission sub-step (0..3), +68 s32. Setter of the flow state: 0x8330C890(state) (exit old, store, enter new, update new). Rules pointer `*0x83C1D218`, **rules+36 = ruleset selector** (the only rules field that the flow reads).
- Other bytes: `0x83AC5F60 + {14, 22, 24, 26}` (u8 flags: 14 = no-rules mode, 22/26 = frontend/scripted-flow gates [guess], 24 = custom shootout rounds in use), mode object ptr `0x83BFE99C` (+24 -> +16 = game-mode variant, same as RuleGate in docs/l2-penalty.md; +4 -> +384 = custom shootout rounds byte).

## Exact decision rules (0x8331DFE8) [read]
`zero` = clock_sec == 0 and clock_sub == 0. Order of tests:
1. flag byte 0x83AC5F6E set and `zero` -> **0 (game over)**.
2. by `kind` (B+432):
   - **2** (third period): not zero -> 1. Goals differ -> 0. `ruleset == 5` -> 0 (tie ends the game). `ruleset == 1` -> **2 (shootout, no OT)**. otherwise -> **1 (play OT)**.
   - **3** (any OT): goals differ -> 0 (**sudden death, checked while the clock runs**). Clock not zero -> 1. Then `ruleset 3 or 4` -> 0 (tie after OT), `ruleset 2 or 7` -> **2 (shootout)**, otherwise -> 1 (another OT period, playoff style).
   - **255**: result of ShootoutDecision (0 decided / 2 go on).
   - **238**: F+36 bit 0x00800000 set -> 3 (restart) else 1 (a debug-style event fires first if the clock is zero and attempts >= 6).
   - kinds 0 and 1: 1.
Consequences: ruleset 0, 6, 8+ behave like playoff rules (repeat OT until a goal; OT length 20:00, see PeriodLength); 2/7 = 5:00 OT then shootout; 3/4 = 5:00 OT then draw; 1 = no OT, straight to shootout (PeriodLength keeps 20:00 for kind 3 but it is never played); 5 = draw after regulation. "Number of regulation periods" is the literal 2 in the kind test (kind 2 = last regulation period); kinds come from `min(index, 3)`.

## Data fields to change for a custom mode
- Rules-driven (no code): **rules+36** picks among the six behaviours above (cheapest: set it before the game; mapping key -> offset still needs the descriptor at 0x8316AAB8, not done here). 3-on-3 OT format is also keyed on rules+36 (OvertimeReduce/RuleGate in 0x8331F540, docs/l2-penalty.md).
- Shootout rounds: byte at `(*(0x83BFE99C+4))+384` with byte 0x83AC5F78 != 0 (custom), else variant-based 3 or 5.
- Not data (needs a hook): 2 or 4 regulation periods, "no OT but keep other rules", shootout-only (partly exists: 0x8341C8C8 starts kind 255 when 0x8330C998(0) == 2 and 0x8331F0A8 handles 255/238 at match start), sudden-death variants (first-to-N goals, mercy rule).
- Recipes (all through a replacement of EvalPeriodEnd, which returns only 0/1/2/3):
  - **2 periods**: treat `kind == 1` as the last regulation period: apply the kind-2 branch there; and PeriodLength/SetPeriodIndex must make kind 2 not appear (or map later periods to kind 3). 
  - **4 periods**: kind is capped at 3 by SetPeriodIndex, so a 4th regulation period collides with "overtime"; either remap index 3 to a kind 2 clone (hook SetPeriodIndex/StartPeriod so kind stays 2 while index < 4 and the last-period test uses the index) or accept that kinds repeat. The tests `kind == 2` in EvalPeriodEnd then become `index == last`.
  - **No OT / draw**: return 0 for the tie case (ruleset 5 already does it); **shootout only**: return 2 for the tie case (ruleset 1 does it); **shootout-only game**: start in kind 255 (the 0x8341C8C8 route).
  - **Sudden death / first to N**: hook goal-based exit: return 0 when `|diff| >= N` for any kind (currently only kind 3 ends on a goal).
  - **Always-OT / more OT periods**: ruleset not in {1,2,3,4,5,7} gives repeat OT; OT length by PeriodLength(3).

## Hook-point ranking (leverage / risk)
1. **0x8331DFE8 EvalPeriodEnd** (pure, ~130 insns, 6 callers-chain through 0x83326280, 0x8331F5D0, 0x8348D770). One replacement controls game over / continue / shootout. Risk low; verify mode cheap (compare return value). Fully readable now.
2. **0x833FB500 SetPeriodIndex / 0x833FB558 NextPeriod** for the kind remap (4 periods) and **0x83475D50 PeriodLength** (length per kind).
3. **0x834039E0 ShootoutRounds** (tiny, shootout length) and **0x8331DED0 ShootoutDecision** (decoding incomplete; hook the rounds only).
4. **0x83328930** (state 10 update) for the "what happens next" gate (SetState 9 vs 1 vs shootout setup); **0x83326280** as the observation point for stoppages (log reasons and F+52). Larger, more side effects.
5. Observation only: the event fire functions 0x8331F408, 0x8339B0C8, 0x83316108, 0x8331F150, 0x8331F4B8 (payload and ordering; not decision points).

## Unknowns

The state-5 update sets F+36 bit 0x40000000 at zero and enters state 10, but which caller of 0x83481038 / 0x83326280 raises the horn stoppage (reason code) was not isolated. Also where bit 0x40000000 is cleared (it blocks the start-period call in state 10).
- Exact bit-level rules of ShootoutDecision (round pairs, sudden death), meaning of B+186/188/190, B+201, B+203, F+4/+8/+16/+68, and what flow states 0..13 are in game terms (states 1, 5, 9, 10 inferred: faceoff/period start, play/post-whistle, game over, intermission).
- Mapping of rules keys to rules+36 values 0..7 (inferred only); the event-slot to purpose mapping for the game-over event (sole user match only).
- Verification: none (no game run). A verify-mode hook comparing EvalPeriodEnd's return with the readable version in a normal game plus an OT game is the first step.

## Module 4: readable implementation (src/l2/gameflow.{h,cpp}, gameflow_hooks.cpp)
Covers **EvalPeriodEnd 0x8331DFE8** and **ShootoutRounds 0x834039E0** as pure C++ over an `Env` (same pattern as rules.h; `FlowEnv` derives from `rules::Env`). Re-read against the lifted code: the decision table above is exact (clock tests are s16 on both words; kind 2 tests the clock first, kind 3 the goal difference first; rules pointer `*0x83C1D218` is dereferenced without a null check). New facts: the goal difference 0x833FADA0(0) = goals(side 0) - goals(side 1) (via 0x833FAD58 per side, through a guest object chain: modelled as `FlowEnv::Goals`, the guest env calls the original); only zero-ness matters in stock rules. The restart bit lives at 0x83C1D244 (flow struct +36).
- **Not taken over:** kind 238 (the original fires diagnostic UI events when the clock is zero and attempts >= 6; the hook always runs the original there) and the body of ShootoutDecision 0x8331DED0 (kind 255 calls the original through `FlowEnv::ShootoutDecision`, it has side effects).
- **cvar `nhl_l2_gameflow`** (env `REX_NHL_L2_GAMEFLOW`): 0 off (default), 1 verify (readable result vs original r3, no shadow overlay needed because both functions are pure; kinds 238/255 are counted as `skipped`), 2 replace. Log: first 25 `[nhl-l2] MISMATCH EvalPeriodEnd|ShootoutRounds ...`, and once a second `[nhl-l2] gameflow mode=.. calls/mismatches/skipped: ...`.
- **Custom game end (default off, mode 2 only):** `REX_NHL_GAME_END_MODE` = 0 stock; 1 first to N goals (`REX_NHL_GAME_END_GOALS`, default 5): any side with >= N goals ends the game at the next stoppage in kinds 0..3 (this is the stoppage-time check only: EvalPeriodEnd runs after every stoppage, so the game ends at the first whistle after the goal, which is also when the stock sudden death ends); 2 no overtime: a tie after the last regulation period is a draw (like ruleset 5); 3 a tie after regulation goes to a shootout (like ruleset 1). Designed but NOT implemented: 2/3/4 regulation periods (replace `kind == 2` with an index test, needs SetPeriodIndex/PeriodLength cooperation, see "Data fields to change").
